# 0.3.0

This release brings router-style Administration and a focused network Dashboard
to the same Home Assistant integration. The integration domain remains
`speedport_smart`; no separate dashboard installation is required.

These notes describe the combined 0.3.0 candidate. The stable release has not
been published; the candidate must pass its checks and owner testing before the
release pull request is merged. Earlier beta results do not validate later edits.

## Highlights

- **Dashboard:** a WAN download/upload graph with selectable 5-, 15-, 30- and
  60-minute windows, defaulting to 15 minutes, with mouse, touch and
  keyboard sample inspection and larger, clickable rate readouts; Wi-Fi band
  summaries; DSL speeds; separate LTE/5G receiver information; and reported Ethernet link
  rates for wired devices. History uses
  Home Assistant Recorder and the existing live stream, not extra router polls.
  Changing the timeframe reads the selected history from Home Assistant.
  Displayed points retain actual observed values and timestamps; missing
  history is not filled with invented traffic.
  Summary cards fill the available row width and stack on smaller screens.
  Download and upload readouts stay side by side, including on mobile. Their
  values and Mbit/s units remain together on one stable line rather than
  shifting as values change; the redundant "Latest sample" subtitle is removed.
- **Transferred volume:** a separate downloaded/uploaded graph adds valid
  nonnegative differences between recorded cumulative counters and incoming
  live counters, not estimates integrated from the rate graph. Both graphs
  share the 5-, 15-, 30- and 60-minute window selector; volume uses decimal MB,
  GB or TB. The first in-window counter is only a baseline. Resets,
  stale/unavailable samples and long gaps break segments and mark usable
  subtotals partial instead of inventing traffic. This adds no router calls,
  does not interpolate the window boundary and does not change Recorder.
- **Administration:** Overview, Status, Internet, Telephony, Network and System
  follow the 69 screens observed in the Speedport Smart 4R Typ A interface.
  Existing settings load inline on page entry. Each form keeps its own draft,
  target, Refresh, Cancel and confirmed Save controls. Supported settings have
  one styled editor, without a second legacy entity control for the same setting.
- **Private IP information:** the Internet IP address page reads the native
  IPv4/IPv6 addresses, gateways, DNS servers and reported IPv6 prefixes on demand.
  Missing values are shown as unreported. Results remain administrator-only and
  are not added to entities, Recorder, diagnostics or browser storage; there is
  no new background polling.
- **Broader configuration:** reviewed Internet/DNS, Wi-Fi, DHCP, forwarding,
  parental rules, telephony, phonebooks, storage, VPN and system operations,
  including explicitly guarded maintenance and private file transfers.
- **WAN polling:** Auto starts at 5 seconds and moves through 4, 3, 2 and
  1 second after five consecutive successful WAN reads at each cadence.
  The 1-second cadence also needs five successes before it is marked Stable.
  A polling failure for a supported WAN source resets the success count and
  enters a fixed 60-second Cooldown, then retries the same cadence. Repeated
  failures restart that same cooldown rather than increasing it. Manual mode
  keeps its requested slot interval and uses the same failure cooldown. WAN
  scheduling uses fixed slots rather than response completion plus another
  interval. Missed slots are skipped without overlapping requests or catch-up
  bursts. The footer separates the target from observed sample spacing. Rates
  use the latest two valid counter observations and their actual elapsed
  monotonic time, with no rolling average or held nonzero tail. Repeated totals
  do not prove a fixed router-counter refresh interval. Recorder history remains
  enabled. WAN reads stay in the Fast sequence, avoiding an additional request
  immediately after a Normal or Slow protected session. Normal DSL reads retain
  bounded busy retries, and long active operations can still delay samples.
- **Panel priority:** a connected, visible and focused Dashboard prioritizes
  WAN work; Administration prioritizes explicit settings operations. Automatic
  Normal and Slow reads wait, keeping their original data timestamps. Leaving
  or hiding the panel, losing focus or disconnecting releases the lease, with
  a 45-second expiry for lost clients. In-flight operations finish normally;
  missed background updates are not replayed. The footer exposes priority and
  deferred background work without changing the configured polling intervals.
- **Recovery and diagnostics:** page-scoped reads, exact control readback,
  clearer unavailable reasons, private settings-session recovery, and drafts
  that survive normal WAN updates without replaying writes. WAN graph freshness
  uses the newest valid successful sample timestamp rather than minute-rounded
  diagnostics. The new chart fix tolerates a Home Assistant clock up to five
  seconds ahead of the browser for live samples, retaining their original
  timestamps. Larger clock leads, stale data and unavailable rates remain
  rejected. This display-only fix does not change the polling policy above.
  Receiver LED and bonding editors also obtain missing device identity from a
  fixed receiver-information read, rejecting absent or conflicting identity
  without replacing the current mode values. The LED settings editor accepts
  the firmware's symbolic `On`, `Timer` and `Off` values as well as its numeric
  codes. Confirmed prerequisite failures now explain why editing remains
  disabled instead of showing only a generic loading error.
  Newly available inline sections load without replacing other forms' drafts;
  if a save is running, their reads wait for its result and are cancelled when
  the page, router or administrator context changes.
- **Discovery:** DHCP and SSDP hints receive a read-only model/identity check
  before setup. Discovery never silently moves an existing entry or sends its
  saved password to a newly announced host.

## Upgrade from 0.2.0 or a 0.3.0 beta

1. Take a Home Assistant backup before upgrading. Keep local access to the
   router and its password available.
2. Update the existing **Telekom Speedport Smart** repository through HACS to
   **0.3.0** after that stable release is published. Beta users can select the
   stable version and turn off prereleases if they want only stable updates.
3. Restart Home Assistant, then reload the dashboard browser page to replace
   older frontend modules. Do not remove and re-add the integration.
4. Use **Logout** in any open router web interface before checking protected
   settings in Home Assistant. Closing the browser tab alone may retain the
   router's management session. A router restart is not an upgrade step.
5. Check WAN history, device presence, actual polling cadence, and one
   Administration page read. An unavailable field can mean that its specific
   hardware, firmware, permission or management-session prerequisite is absent.

Retained entities keep their identifiers and existing history. Upgrade cleanup
removes nine obsolete beta router-control placeholders and three unproven
router-global NAS placeholders, as well as the retired router event entities.
Review automations that used those removed entities. The supported, guarded
operations and per-share information are in Administration; placeholder removal
does not change any router setting. WAN history is not disabled or erased.

## Compatibility and important limits

- Home Assistant **2025.12.0 or newer**; bundled brand images require
  **2026.3 or newer**. Older supported versions may show a generic icon.
- Live read-only validation and reviewed management contracts target
  **Speedport Smart 4R Typ A**, firmware **010152.5.0.001.0**. Other models and
  firmware versions are not promised equivalent configuration support.
- The integration and main Dashboard support English and German. The expanded
  Administration editors currently use English. Both Home Assistant themes
  remain supported.
- Navigation coverage is not a claim that every operation is implemented.
  Missing or partial cases remain explicit in the
  [capability matrix](https://github.com/aarikmudgal/ha-speedport-smart/blob/v0.3.0/docs/MANAGEMENT_CAPABILITY_MATRIX.md).
  Examples include complete Hybrid exception creation, LAN IPv6/ULA writes,
  Wi-Fi environment scanning and parts of the VPN lifecycle.
- **Expanded router writes have not been live-tested by this development work.**
  Firmware inspection, offline tests and read-only observations do not prove
  router acceptance or recovery. Stable release numbering does not remove that
  limitation. Network, password, firmware and reset operations can interrupt
  access or remove settings. Read each warning and keep a recovery path.
- An offline field-rendering audit covers **110 advertised settings contracts
  and 454 fields**, including input types, fresh-read editing gates, blank secret
  fields and the absence of automatic saves. This is not live write validation.
  The read-only audit identified a separate LED parser mismatch: the typed
  editor rejected valid symbolic firmware values. Offline regressions cover
  that mismatch, prerequisite explanations and deferred page recovery. The
  owner still needs to validate the combined candidate before stable
  publication, including both graphs, window changes, focus transitions,
  preserved history and private page reads. Offline results alone do not
  establish their behavior in the installed dashboard.
- Passwords are not prefilled. Contacts, call lists, credentials and private
  downloads stay out of normal entities and Recorder. Downloads such as backups,
  Router-Pass, VPN files and system logs can contain secrets and must be handled
  privately. An uncertain write is never retried automatically.

## Recovery

For a regression, retain redacted diagnostics and the installed version. Restore
the Home Assistant backup when a full rollback is needed; changing only the
integration files does not undo entity-registry cleanup. Home Assistant rollback
also cannot undo a router setting changed separately by the user.

HACS default-catalog inclusion is a separate review process. Until accepted,
installation remains available through the HACS custom repository.
