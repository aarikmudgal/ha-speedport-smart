# 0.3.0 release checklist

Prepared on **3 September 2026**. This separates preparation from publication
and owner testing; unchecked external steps must not be inferred from local
files or earlier beta results.

## Candidate contents

- [x] Source manifest and `pyproject.toml` declare **0.3.0**; domain remains
  `speedport_smart` and HACS installs the integration plus dashboard together.
- [x] Dated changelog, comparison links, [release notes](0.3.0.md), upgrade and
  recovery guidance are prepared.
- [x] Capability and architecture documentation distinguishes 69 observed
  navigation screens from partial/unsupported operations and untested live writes.
- [x] Removed beta placeholders, frontend reload, retained entity history,
  English-only expanded editors and management-session behavior are documented.
- [x] Private IPv4/IPv6 page reads, single styled settings editors, receiver
  identity prerequisites, symbolic LED values, guarded loading errors and
  deferred sibling-section recovery are documented. Final candidate owner
  testing remains pending; successful live router writes are not claimed.
- [x] Stable publication attaches versioned notes; feature branches retain
  automatic, separately versioned beta releases.
- [x] Five-success Auto cadence learning and fixed 60-second WAN Cooldown are
  documented separately from rate calculation and graph display.
- [x] Fixed-slot WAN scheduling, consecutive-sample rates without rolling
  averaging, focus-based priority and deferred background reads are documented
  without promising exact router response or counter-refresh timing.
- [x] The rate and transferred-volume graphs share a 5-, 15-, 30- or 60-minute
  window, initially 15 minutes. Volume comes from observed byte-counter deltas,
  with automatic MB/GB/TB units and explicit partial coverage, not rate
  integration, additional router polling or changed Recorder settings.
- [ ] Dark-mode desktop (1920 × 1080) and mobile (430 × 932) Dashboard previews
  are refreshed from the combined frontend using dummy data only. Verify both
  graphs and ensure no private router data appears.
- [ ] Final candidate CI passes minimum Home Assistant, pinned-current Home
  Assistant, frontend/package, Hassfest and HACS jobs without ignored checks.
- [ ] Owner reviews the final candidate and any remaining limitations before
  merging the release PR. No new router-write validation is claimed.

## Compatibility evidence

Earlier betas are comparison evidence, not validation of this combined release
candidate. [Beta.62.1](https://github.com/aarikmudgal/ha-speedport-smart/releases/tag/v0.3.0-beta.62.1),
from `4ed87c4`, is the preceding published runtime baseline. It does not contain
the newly combined transferred-volume graph and stable-release preparation.

The candidate retains fixed-slot scheduling and the latest-two-counter rate
method. It does not restore the earlier five-second average or insert WAN reads
between protected Normal work and DSL reads. Background work waits under panel
focus, and concurrent refreshes share their existing in-flight operation rather
than replaying queued timer calls. A one-second request target is not evidence
of a guaranteed one-second source update. Long active operations can still
delay samples. No live router-setting validation is claimed.

release. When updating either pin, inspect its declared Home Assistant dependency,
choose a stable release and rerun CI. The installed fixture dependencies, not a
job's name, define what was tested.

## Publication and owner sign-off

- [ ] Merge the reviewed release PR only after owner testing; do not create or
  move stable tags manually.
- [ ] Confirm successful main-push CI, then the automatic Release workflow.
- [ ] Verify **v0.3.0** is a non-draft, non-prerelease full release targeting
  the tested main commit, with a version-only title, `speedport_smart.zip`,
  `SHA256SUMS` and release notes.
- [ ] Verify archive digest, flat integration layout and packaged version **0.3.0**.
- [ ] Owner upgrades through HACS, restarts HA and reloads the panel; checks
  preserved WAN history, entity presence, settings reads and both themes.
- [ ] Check clean installation/removal separately when an appropriate test
  instance is available. Do not infer those results from an upgrade alone.
- [ ] Only after stable installation is confirmed, update the existing HACS
  submission with the actual release and validation evidence.

The release does not imply that disruptive settings, firmware updates, resets,
credential changes or other router writes were exercised. Those require separate,
explicit owner testing and recovery evidence. Preparing this release changes no
router settings.
